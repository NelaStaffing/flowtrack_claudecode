# Milestone Update Fix - Migration 20260106

## Problem
Milestone changes (like due date, status, description) were not saving to the database.

## Root Cause
The RLS (Row Level Security) policy on the `milestones` table was too restrictive:
```sql
-- Old policy - only milestone creator could update
CREATE POLICY "Users can update their milestones" ON milestones
  FOR UPDATE
  USING (created_by = auth.uid());
```

This prevented:
1. Team members from editing milestones they didn't create
2. Updates to milestones that don't have `created_by` set

## Solution
Updated the RLS policy to allow any authenticated user to update milestones:
```sql
-- New policy - any authenticated user can update
CREATE POLICY "Users can update milestones" ON milestones
  FOR UPDATE
  USING (auth.uid() IS NOT NULL);
```

## How to Apply This Migration

### Option 1: Supabase Dashboard (Recommended)
1. Go to your Supabase project dashboard
2. Navigate to **SQL Editor**
3. Copy and paste the contents of `20260106_fix_milestone_update_policy.sql`
4. Click **Run**

### Option 2: Supabase CLI
If you have the Supabase CLI installed:
```bash
supabase db push
```

### Option 3: Direct SQL
Run this SQL in your database:
```sql
DROP POLICY IF EXISTS "Users can update their milestones" ON milestones;
CREATE POLICY "Users can update milestones" ON milestones
  FOR UPDATE
  USING (auth.uid() IS NOT NULL);
```

## Testing
After applying the migration:
1. Open a milestone detail drawer
2. Edit the due date or any other field
3. Click "Save Changes"
4. Refresh the page and verify the changes persisted
